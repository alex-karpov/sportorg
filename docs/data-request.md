## Персональные данные: правило
Решение мейнтейнера `[мейнтейнер: 2026-10-24]`, вариант (а): корпус живёт вне репозитория, в приватном хранилище мейнтейнера; в репозиторий не попадает ни один файл с реальными ФИО, годами рождения или номерами чипов; в репозитории — скрипт анонимизации и хэши оригиналов. Позже можно перейти к варианту (б), анонимизированному корпусу в репозитории; обратного пути нет, потому что публичную историю не отозвать. Что именно маскировать (ФИО, даты, номера чипов, клубы, данные детей) — решение до этапа 2. Решено: Д1 в `docs/reports/stage-2-prompt.md` `[мейнтейнер: 2026-10-31]`.

Связанная находка: шаблоны протоколов в legacy (`.docx`) содержат один адрес e-mail и три номера телефона, а в свойствах документа — имена авторов (`docs/evidence/stage-0/legacy-layout/README.md`, раздел 3). Решение мейнтейнера от 2026-10-25: в опубликованный репозиторий шаблонов `alex-karpov/sportorg-templates` `.docx` не входят, кроме одного диплома, очищенного мейнтейнером. Скан перед публикацией ничего не нашёл (там же, раздел 4). Десять `.docx`, которые upstream опубликовал раньше, остаются в истории его репозитория.

## Как готовить корпус (п. 1–2)

Срок — до начала сессии S3 этапа 2 (Д4) `[мейнтейнер: 2026-10-31]`. Ниже описано, как собрать корпус, чтобы файлы годились как эталон. Поведение legacy проверено по коду закреплённого коммита `pysport@b548c35`.

### Файлы передаются нетронутыми
- **Оригинал не открывать в SportOrg.** При открытии legacy заново считает все результаты `[код: pysport@b548c35 sportorg/modules/backup/json.py:44]`. Если включено автосохранение, программа потом сама перезаписывает файл `[код: pysport@b548c35 sportorg/gui/main_window.py:267-273]`. Места и статусы, сохранённые в файле, — второй эталон: так посчитала версия, работавшая в день старта. После пересохранения там окажется расчёт новой версии. Файлы копируются с ноутбука старта или из резервной копии, сразу получают атрибут «только чтение», дальше работа идёт только с копиями. Открывать в legacy можно только копию без этого атрибута: файл gzip с атрибутом «только чтение» legacy не открывает (`PermissionError`), а обычный открывает, но молча не сохраняет и оставляет рядом `.json.tmp` (F7, ошибка legacy `[мейнтейнер: 2026-11-01]`; `docs/evidence/stage-2/corpus/findings.agent.md`).
- **Копия байт в байт.** Не перекодировать, не распаковывать, не менять расширение. Legacy сохраняет и в gzip, и в UTF-8, и в кодировке системы `[код: pysport@b548c35 sportorg/modules/backup/file.py:35-50]`. В старых файлах поля называются по-старому, а ключа `races` может не быть `[код: pysport@b548c35 sportorg/modules/backup/json.py:55, 84-118]`. На таких файлах и нужно проверять шов и анонимизатор.
- **Хотя бы один файл не в UTF-8.** Судя по коду, файл в cp1251 откроется на русской Windows, а на Linux, где работает оракул, не откроется ни с первой, ни со второй попытки `[допущение по коду: pysport@b548c35 sportorg/modules/backup/file.py:37, 48]`. Проверяется в S2.
- **Протокол соответствует тому же состоянию файла.** Лучше всего подходит пара: финальный файл после протестов и финальный опубликованный протокол, желательно подписанный. Если файл правили после печати протокола (протест, снятие, перевод в другую группу), это записывается в паспорт. Иначе расхождение отнесут не к той причине.

### Какие гонки: важно разнообразие, а не количество
Каждый файл добавляет новое сочетание параметров, от которых зависит расчёт в legacy:

| Параметр | Варианты в legacy |
|---|---|
| Тип гонки | индивидуальная, гонка преследования, эстафета, многодневка `[код: pysport@b548c35 sportorg/models/memory.py:67-71]` |
| Режим подсчёта | время, очки (рогейн), ARDF `[код: pysport@b548c35 sportorg/models/result/result_calculation.py:145-146]` |
| Маркированная трасса | `marked_route_mode` ≠ off `[код: pysport@b548c35 sportorg/models/result/result_checker.py:116]` |
| Выбор | `is_any_course` `[код: pysport@b548c35 sportorg/models/memory.py:308]` |
| Система отметки | ручная, SI, SFR, Sportiduino, Impinj, SRPID, Huichang `[код: pysport@b548c35 sportorg/models/memory.py:28-36]` |
| Версия SportOrg | файлы разных лет 2017–2026: на них проверяются миграции старых полей `[код: pysport@b548c35 sportorg/modules/backup/json.py:84-118]` |

Минимум до S3 (6–8 файлов):
- крупная индивидуальная гонка на SI; она же пригодится в S6 для замера времени пересчёта;
- эстафета, лучше с неполной командой;
- многодневка, где кто-то пропустил день;
- рогейн;
- ARDF;
- маркированная трасса;
- выбор;
- самый старый файл из тех, что есть.

Если в файле есть переход через полночь, участники вне конкурса, равные времена, снятия (DSQ, MP, DNF, DNS) или точность времени до десятых, это отмечается в паспорте.

Если полный объём п. 1 к S3 собрать не получается, хватит минимума: он нужен для главного теста анонимизации (пересчёт до и после совпадает). Остальное можно принести до S4. Скрипты S3 детерминированы, на дозагруженных файлах их просто запустят ещё раз.

### Как разложить файлы

```
$SPORTORG_CORPUS/          # вне репозитория, на ext4 в WSL, не в /mnt/c
  inventory.csv            # паспорт; остаётся вне репозитория
  raw/C01/
    <файл гонки как есть>  # только чтение
    protocol/              # PDF/HTML в опубликованном виде, сплиты
    source.txt             # откуда взят файл, ссылка на публикацию
  raw/C02/ …
```

Каталоги называются нейтрально (C01, C02…), без названия гонки: имена каталогов попадут в логи и сводки.

Паспорт `inventory.csv` — шаблон заголовка ниже. Названия столбцов — предложение; S3 может их уточнить, когда будет делать манифест. В манифест репозитория попадают только нейтральные столбцы, от `sport` до `special_cases`. Сам паспорт остаётся вне репозитория: по `source` гонку можно узнать.

```
id,sport,race_type,processing_mode,punch_system,days,persons,version_race_day,resaved_after_race,protocol_kind,protocol_signed,protocol_matches_file,edits_after_print,special_cases,source,may_share
```

| Столбец | Что писать |
|---|---|
| `id` | C01, C02…; совпадает с именем каталога |
| `sport` | ориентирование, рогейн, ARDF, туризм, циклический вид |
| `race_type` | `individual`, `pursuit`, `relay`, `multi_day` |
| `processing_mode` | `time`, `scores`, `ardf` |
| `punch_system` | `manual`, `sportident`, `sfr`, `sportiduino`, `rfid_impinj`, `srpid`, `huichang` |
| `days`, `persons` | число дней; примерное число участников |
| `version_race_day` | версия SportOrg в день старта, если известна. В самом файле записана только версия последнего сохранения `[код: pysport@b548c35 sportorg/modules/backup/json.py:21]` |
| `resaved_after_race` | `yes` (и какой версией), `no`, `unknown` |
| `protocol_kind` | `final`, `preliminary`, `none` |
| `protocol_signed` | `yes`, `no` |
| `protocol_matches_file` | `yes`, `no`, `unknown` |
| `edits_after_print` | что правили после печати протокола; свободный текст без ФИО, он нужен при классификации расхождений |
| `special_cases` | через `;`: `midnight`, `out_of_competition`, `ties`, `dsq`, `mp`, `dnf`, `dns`, `tenths`, `incomplete_team`, `missed_day` и другие |
| `source` | откуда файл, ссылка на опубликованный протокол |
| `may_share` | `yes`, если есть право передать файл для этой работы |

### Состояние корпуса (2026-11-01)
Корпус в работе: мейнтейнер добавляет и заменяет файлы. Числа ниже получены разовым скриптом вне репозитория, который печатает только счётчики и настройки гонок. Их заменит манифест S3.

Манифест S3 (2026-11-01, `docs/evidence/stage-2/corpus/manifest.md`, команда в `commands.txt` того же каталога) подтвердил числа ниже: 25 каталогов, 63 файла гонок (28 gzip, 29 UTF-8, 6 cp1251), 100 гонок, из них 24 разных старта; ARDF и `scores_mode = formula` нет. Оракул на 62 файлах дал одинаковый результат до и после анонимизации; один файл (C02) legacy не открывает ни в оригинале, ни в копии (F8). Файлы gzip с атрибутом «только чтение» legacy, судя по коду, не откроет: он открывает их на чтение и запись (F7 там же).

- 25 каталогов (`C01`–`C07`, `C05b`, `N01`–`N15` без `N11`, `N04b`, `Q2`, `R1`), 63 файла гонок: 28 gzip, 29 UTF-8, 6 cp1251 `[корпус: C01, C03, N10, N15]`. Версии SportOrg от 0.11.0.0 до v1.8.0b2; в C01 есть файл старого формата без ключа `races`.
- Минимум до S3 закрыт, кроме ARDF: файлов с `result_processing_mode = ardf` нет. Нужен до S4.
- Файлов с `scores_mode = formula` нет (R22). Системы отметки в файлах — только SportIdent и ручная.
- Во многих каталогах лежат файлы отдельных дней вместе с общим файлом; счётчики у них совпадают. Манифест помечает такие файлы, а не считает их разными гонками.
- `files.tsv` (столбцы `dest`, `sha256`, `size`, `source`) есть во всех 25 каталогах. Хеши перечисленных файлов совпадают. Расхождения: в N04 удалены два PDF, которые в `files.tsv` остались (это не протоколы); в N13 добавлен скан протокола, которого в `files.tsv` нет.
- `inventory.csv`: 25 строк, заполнены только `id`. Тип гонки, режим подсчёта и версию скрипт возьмёт из файла; `sport`, `may_share`, `protocol_*`, `edits_after_print`, `special_cases` знает только мейнтейнер.

### Д3 на практике
- **Схема запрета** `[мейнтейнер: 2026-11-01]`. Агенту закрыты Read и `cat`, а скрипты в песочнице корпус читают. В `.claude/settings.local.json` (машинный файл, в git не входит):
  ```json
  "sandbox": { "filesystem": { "allowRead": ["~/src/corpus/raw", "~/src/corpus/inventory.csv"] } },
  "permissions": { "deny": ["Read(~/src/corpus/**)", "Bash(cat *src/corpus*)", "Read(~/.config/sportorg/**)"] },
  "env": { "SPORTORG_CORPUS": "/home/ank/src/corpus" }
  ```
  - Правило deny для Read действует и на песочницу Bash: Claude Code добавляет пути из правил `Read(...)` в `sandbox.filesystem.denyRead` (документация Claude Code, `settings-reference`, ключ `sandbox.filesystem.denyRead`, прочитано 2026-11-01). Одно правило Read закрывает корпус и для скриптов. Проверено: скрипт получил `FileNotFoundError`, а `ls` отклонил слой разрешений.
  - `allowRead` снова открывает песочнице `raw/` и `inventory.csv`. Открыты подкаталоги, а не весь корпус: документация говорит, что при пересечении правил действует правило с более узким путём, а случай одинаковых путей не описан. Корень корпуса остаётся закрытым и для скриптов.
  - Это защита от случайного чтения, а не барьер. Слой разрешений проверяет только Read, Grep, Glob и команды, которые он распознаёт (`cat`, `head`, `tail`, `sed`, `tee`, перенаправления; на практике и `ls`). Песочница не различает, как процесс получил путь: любой скрипт агента, в том числе `python3 -c`, прочитает `raw/`. Остальное держится на правилах сессии: агент не открывает сырой корпус и запускает на нём только скрипты из `scripts/`.
- **Канарейка** `~/src/corpus/canary.txt` с выдуманным ФИО лежит в корне корпуса, не в `raw/`. Результат проверки 2026-11-01 в свежих сессиях `[мейнтейнер: 2026-11-01]`:

  | Способ | Результат |
  |---|---|
  | Read: `canary.txt`, `inventory.csv`, `raw/C01/files.tsv` | отклонено правилом разрешений |
  | `cat` по `~/…` и по абсолютному пути | отклонено правилом разрешений до запуска |
  | `head` по `inventory.csv` и `raw/…` | отклонено проверкой auto mode; на этот слой не полагаемся, он есть только в auto mode |
  | скрипт через `$SPORTORG_CORPUS`: `inventory.csv`, `raw/C01/files.tsv` | читаются |
  | скрипт: `canary.txt` | не виден (`FileNotFoundError`) |

  Канарейка остаётся в корпусе: проверку повторяют после каждой правки `settings.local.json`, после обновления Claude Code и при независимой проверке этапа (S9). Выдуманное ФИО не должно совпадать с ФИО человека из корпуса.
- **Кто запускает скрипты.** Агент, в песочнице, по схеме выше. Если корпус закрыть и для песочницы, команды запускает мейнтейнер (`! uv run …` в сессии Claude Code), а агент видит только их вывод.
- **Что печатают скрипты.** Скрипты, работающие с корпусом, включая проверку утечек, печатают только счётчики, хеши и нейтральные id, но никогда не найденную строку. Иначе сама проверка утечек отправит данные в API модели. Имена файлов внутри каталогов гонок содержат названия стартов (R21), поэтому сводки называют файлы по id каталога и хешу имени.
- **Ключ анонимизации** создан один раз и хранится в менеджере паролей `[мейнтейнер: 2026-11-01]`. Копия лежит в `~/.config/sportorg/anonymization.key` (права 600, закрыт правилом `Read(~/.config/sportorg/**)`). Скрипты получают ключ из переменной `SPORTORG_ANONYMIZATION_KEY`, которую задаёт профиль оболочки; в свежей сессии агента она видна. Ключ не печатается и не попадает в разговор: команды `! …` и `settings.local.json` для него не используются. Если ключ потерять, с новым получатся другие псевдонимы, и сводки в evidence изменятся.

### Что не нужно
- Пересохранённые копии и выгрузки в Excel или HTML вместо исходного файла гонки.
- Логи (п. 5) и резервная память станций (п. 4) с тех же стартов пригодятся, но на S3 и S4 не влияют. Если они есть, их кладут в каталог гонки (`logs/`, `dumps/`), правила те же.
